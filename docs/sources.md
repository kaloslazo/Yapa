# Fuentes consultadas

Corte de investigación: **19 de septiembre de 2026**. Se priorizaron documentación oficial y fuentes primarias. Las cifras o capacidades que puedan cambiar deben leerse como una fotografía de ese corte.

1. GitHub, **Spec Kit Documentation**. Flujo SDD, integraciones y fecha de actualización.
   https://github.github.com/spec-kit/
2. GitHub, **What is Spec-Driven Development?** Filosofía, fases greenfield/brownfield y relación con Contract-Driven Development.
   https://github.com/github/spec-kit/blob/main/docs/concepts/sdd.md
3. GitHub, **Agentic SDD**. Comandos, quality gates, análisis de consistencia y convergencia.
   https://github.github.com/spec-kit/reference/agentic-sdd.html
4. Kiro, **What is spec-driven development?** Requisitos, diseño y tareas antes del código; diferencias frente a vibe coding.
   https://kiro.dev/
5. Kiro, **Best practices for Specs**. Requirements-First, Design-First, importación y sincronización de specs.
   https://kiro.dev/docs/specs/best-practices/
6. Tessl, **Spec-Driven Development package**. Specs versionadas, enlaces a tests y verificación.
   https://tessl.io/registry/tessl-labs/spec-driven-development/2.0.1/files/docs/index.md
7. Piskala, **Spec-Driven Development: From Code to Contract in the Age of AI Coding Assistants**. Niveles de rigor y panorama de herramientas.
   https://arxiv.org/abs/2602.00180
8. Agarwal y Vasilescu, **SPECMINE: A Large-Scale Corpus of Spec-Driven Development Artifacts**. Evidencia de que la práctica y su tooling están creciendo, con preguntas abiertas de investigación.
   https://arxiv.org/abs/2608.25202
9. Thoughtworks, **Technology Radar Vol. 34, abril de 2026**, entrada “GitHub Spec Kit”. Experiencias, beneficios y límites observados en equipos.
   https://www.thoughtworks.com/content/dam/thoughtworks/documents/radar/2026/04/tr_technology_radar_vol_34_en.pdf

## Cómo usar las fuentes

- Las páginas de proveedores explican capacidades y flujos de sus propias herramientas.
- El Radar de Thoughtworks aporta una lectura independiente de adopción temprana, con clasificación **Assess** para GitHub Spec Kit.
- Los papers aportan contexto y preguntas de investigación, no una garantía universal de productividad.
- El resultado del ejemplo de este repositorio es evidencia local y pequeña; no debe presentarse como estudio científico.
